# Deal import retirement and read-only Pipeline

Implemented against verified upstream `main`, `a4af75fce05c35b2378fb41a0c61bb35e6dd52a1`. This is a local implementation and acceptance report. No commit, push, deployment, production access, migration, schema change or historical-data purge was performed. Unrelated auth/password and reporting work in the shared checkout was left untouched.

## Result

The Deals header uses the existing shared `CreateButton` with its Plus icon and **New Deal** label. It opens the existing creation sheet directly, retains `deals.create`, and is disabled without a usable initial stage. The header's default-stage → Lead → first-stage fallback is preserved. As confirmed, the existing form and batch API still save new Deals at Lead; no manual creation or closing rule changed.

Pipeline is an accessible `input` with `aria-label="Pipeline"`, `readOnly`, `value={pipeline?.name ?? ''}`, normal card/foreground theme colors, responsive sizing and `cursor-default`. The select, options and user-switching callback are gone. Sales Pipeline remains the preferred persisted non-archived record, with the existing fallback and authorized `pipelineId`/`highlight`/`dealId` compatibility. Search, filters, refresh, stage management, permissions, record navigation and drag/drop remain working.

Deal Import upload, mapping, preview, review, history, details/results, configuration and handler branches are removed. The six backend history/detail/results/upload/preview/execution routes are unregistered. POST attempts return 404 without writing a job, upload, Deal or audit event. `/crm/deals/imports/:id` has no dedicated page; `/crm/deals/import` and `/crm/deals/imports` can match the existing normal Deal-detail route, whose unavailable-record state exposes no importer. No replacement page or redirect was added.

The active shared import type and registries contain only `leads | contacts | accounts`. CSV-only Deal schemas, resolved-value review behavior and importer-only relationship/pipeline/agent resolution were removed. Generic CSV parsing, limits, transactions, idempotency, upload cleanup, history/results and tenant/module isolation remain. Lead/Contact automatic Deal creation and its cache refreshes remain intact. Tracked shared JavaScript was regenerated by the normal shared build.

## Historical compatibility and remaining references

**No database migration is required.** Prisma schema and all migrations are unchanged. `CrmImportJob`, `CrmImportRowResult`, `CrmImportUpload`, `CrmImportChunk` and `AuditLog` remain. Prisma's `CrmImportModule.DEAL` and the read-compatible frontend `ImportSummary.module` retain the historical discriminator; active module keys exclude Deals. Runtime guards reject a retired/unknown module before scoped database operations rather than widening an undefined module predicate.

Intentional references:

- Immutable migration references remain in the original Deal-import migration, environment retirement, import integrity/normalization and legacy-table retirement migrations. They describe historical tables and retained data, not registered application features.
- Historical payload fixtures remain in normalization/deployment/history-rehearsal tests and inspection tools. The populated SQL verifier rejects a changed historical Deal JSON payload and preserves exact original jobs/results. API/browser rollout verification requires only the three active importers while SQL still covers all historical modules and authenticated workspace coverage remains enforced.
- Negative regression assertions contain retired URLs/module strings to prove their absence or rejection. The new backend regression snapshots historical Deal jobs/results/audit data before and after every retired endpoint attempt and confirms no changes.
- `docs/audits/cleanup-manifest.json`, database audit evidence/inventory/ERD, environment and production-retirement reports, `docs/messages-work-email-files.txt`, and the old `.kiro` CRM modernization and separate-feature proposals remain historical evidence. Existing verification reports have explicit retirement notices. Current API/normalization/QA guidance names only the active importers.
- Remaining `CrmImportModule` references describe the retained three-module importer or persisted database enum. Ordinary uppercase `DEAL` Prisma section comments describe normal Deals, junctions, stage history and actions. `DEAL_*`/`DEALS_*` constants in normal Deal tables, filters, permissions, mock data and Product contracts are unrelated to CSV importing and remain required.

The line-by-line reference inventory is saved outside the repository as `reference-inventory.json` in the evidence directory below. It includes every requested search pattern across tracked files and the added regression/report, including normal uppercase Deal constants. No active runtime references remain to a Deal import page/config/controller/handler.
