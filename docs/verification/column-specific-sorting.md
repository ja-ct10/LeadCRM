# Column-specific sorting

Date: 12 October 2026, Asia/Manila. Base: `9d5d0a3b444d8e4894750edbd029b125e3c384c7`. This change includes the settings-menu placement update and implements the agreed sorting plan. Verification was local; no deployment was performed.

## Behavior

Each column hamburger now sorts only that column. It has no table-wide field picker, pending field checkmark, or unrelated `Current` message. A direction is checked only when the clicked column is the active sort. Only the active sortable column offers default restoration; the action is disabled when the default is already active. Unsupported columns retain their available column actions without borrowing another field's sorting choices. Menus with no usable actions are omitted. Pinned headers use the same behavior, and `aria-sort` appears only on the active visible header.

Table settings retains **Manage Columns** and **Reset Column Size**, and adds **Sort Table…**. The existing dialog/portal primitives supply a compact dialog with the actual current sort, all supported fields including hidden ones, direction, Apply, Cancel and default restoration. Field/direction browsing changes only the dialog draft. Apply and default restoration use the existing preference hook; Cancel, Escape and dismissal do not change sorting. Closing returns focus to the settings trigger. Changing sorting returns to page 1 and preserves search, filters, page size and column preferences. Hiding a sorted column preserves its sort, which remains reachable through settings.

| Value kind | Ascending | Descending |
| --- | --- | --- |
| Names, company, email, locations, sources, role, groups and status | Sort A–Z | Sort Z–A |
| Dates | Oldest first | Newest first |
| Company size | Smallest first | Largest first |
| Phone identifiers | Sort ascending | Sort descending |
| Numeric values in compatible grids | Lowest first | Highest first |

The existing allowlists remain unchanged: 10 Lead fields, 8 Contact fields, 6 Account fields, 4 Task fields, 3 Workflow fields, 2 Campaign fields and 6 User fields. Alphabetical status sorting uses displayed labels; no business-priority order or additional supported fields was introduced. The live Deals route remains a board. Its compatible grid receives the shared menu behavior.

## Data correctness

Contacts' Company ordering now uses stored Company text, matching the cell, rather than a linked Account name. First Name compares the first-name field alone; it no longer implicitly appends Last Name. Combined Name remains an explicit projection.

Lead text sorting and Task title sorting reuse the existing natural, case-insensitive comparison helper before pagination. Text is trimmed, empty values remain last in both directions, and equal values use stable ascending record IDs. Lead status keys are normalized to their displayed CRM labels. Workflow status uses one shared display-label function in the grid and backend key projection, so a legacy inactive ACTIVE record sorts as its displayed Paused label. Lead/Task date ordering remains in the database. Task title key selection and page hydration retain a repeatable-read transaction.

All reads use the existing tenant/filter/record predicates. No endpoint, sort parameter, stored preference shape, database schema, permission rule or fetching mechanism changed. New shared/frontend types describe sort-option value kinds and direction wording. The generated `record-sort.js` companion was regenerated by the workspace build.

## Limits

Verification uses real local API/SQL data; the deployed environment was not tested or changed. Background EventSource streams are paused only in the browser forwarding harness because it buffers infinite responses, so the explicit manual refresh count excludes concurrent streaming activity. Manual screen-reader testing and axe scanning were not performed. The focused suites passed; the full repository suite and large-tenant performance profile were not run. Natural text sorting reads matching keys before hydrating a page, following the existing server helper, so very large matching collections still need separate load benchmarking.
