## Consumer and data map

The active Accounts and Contacts routes mount their domain pages and shared DataGrid. Campaigns, Workflows and Users use `useModuleTableColumns`; Tasks uses its existing permission/identity-aware preference hook. **The current Deals route mounts `PipelinePage`, a kanban board.** `DealsDataGrid` and its module config have no active page consumer. Their supported metadata remains compatible; this change does not replace the live Sales Pipeline with a new table.

All table fields below are presentation choices. Hiding fields does not grant or deny access; registered backend routes enforce authenticated tenant identity, module grants and CRM record scope. Required visibility preserves each module's own existing identity; Leads' fixed-first Name rule is not imposed on Contacts, Accounts, Deals, Campaigns, Workflows or Users.

## Findings and corrections

- **P1 — Width persistence:** all active non-Lead table callers were missing resize-end persistence. Tasks additionally discarded saved widths during normalization. Callbacks now use the existing preference API; Task Save, Reset and successive resizes are serialized and failed writes restore previous columns. Width normalization agrees with the existing 80–800 integer schema.
- **P1 — Task reset resolution:** Reset previously POSTed system defaults. It now DELETEs the current user's preference and accepts the server's authenticated tenant/system fallback. Rejections propagate so the shared drawer can preserve the draft and show retry.
- **P1 — Company / Account mapping:** Contact Company previously used the Account name helper, conflating stored company text with a relationship. Company now uses its canonical API display projection, while optional Account links use its stable FK. A company string never becomes a link identity. The unmounted Deal grid follows the same rule.
- **P2 — Selector/configuration mismatch:** Accounts Website was offered as a sort in module config despite lacking API support. Shared Accounts/Contacts/Deals definitions and sort lists now feed client registries, grid and module configs plus server preference metadata. Accounts default orders are contiguous. Campaigns/Workflows/Users are registered as supported frontend fallbacks.
- **P2 — UI affordances:** CRM headers had a hide callback with header menus disabled; wiring now enables the existing menus. Accounts/Contacts/Tasks Manage Columns captures the actual triggering element. Existing documented CRM identity pinning is now supplied to DataGrid. Task Action metadata now declares its pre-existing first-position normalization rule so drawer movement cannot disagree; this module-specific action rule does not impose Leads Name on unrelated modules. Task dates use the established Manila formatter.
- **Investigate — Scale:** Accounts/Contacts/Workflow text sorting uses the existing all-candidate `sortedPageIds` helper; Users and Deals kanban load all authorized pages before local filtering. These preserve across-page correctness but need real tenant volume/query-latency measurements. No performance claim is based on synthetic browser data.

Module IDs and visibility choices remain stable; no fields are retired from these modules. Users retains the documented Department→Groups migration. Reduced Leads and generic saved-order reconciliation are handled by the companion shared mechanics implementation. No new datastore, API route, query cache or custom-field table feature is introduced.
