🔄 Lead → Deal → Invoice — Complete Data Flow

1

Lead Capture

Contact created with source, email/phone, default status=WARM (score=75). Plan limit checked. ownerId set to creating user (immutable). Workflow trigger contact.created fires non-blocking.

ContactAuditLog: contact.createdWorkflowEngine (async)
2

Lead Qualification

Sales Rep engages contact. Status updated to HOT (score auto-updated to 95). Workflow trigger contact.status_changed fires → may create follow-up tasks, notifications, send emails.

Contact (status=HOT, score=95)AuditLog: contact.updatedTask (auto-created by workflow)Notification
3

Deal Creation

Sales Rep opens Pipeline → creates Deal. Plan limit checked. ContactDeal junction entry created for multi-stakeholder deals. DealStageHistory initialized with first entry. Workflow trigger deal.created fires.

DealContactDealDealStageHistory (entry 1)AuditLog: deal.created
4

Stage Progression

Deal moves through stages. Each move: updates stageId, stamps Deal.updatedAt, creates DealStageHistory (with timeInPrevStage in minutes). Trigger deal.stage_changed fires on each move → workflows may auto-create tasks.

Deal.stageId updatedDealStageHistory (per move)WorkflowExecutionRun + Steps
5

Decision Point

✅ Deal Won

Stage.isWon=true → Deal.closedAt stamped. Trigger deal.closed_won. Contact.status → CLOSED. Invoice created linked to Deal.

Deal.closedAtInvoice (created)Trigger: deal.closed_won
❌ Deal Lost

Stage.isLost=true → Deal.closedAt stamped. lostReason required. Trigger deal.closed_lost. Contact.status may → COLD.

Deal.lostReasonDeal.closedAtTrigger: deal.closed_lost
6

Service Delivery (Optional)

ServiceOrder created and linked to Deal. Assigned to Technician. On completion: photos/signature URLs stored (object storage — never base64). Asset registered to Organization.

ServiceOrderAssetAuditLog: service_order.completed
7

Payment

PayMongo payment link generated. Webhook received → HMAC signature validated → idempotency checked via paymongoPaymentId unique constraint. Invoice.paymentStatus → Paid. PaymentTransaction created.

Invoice.paidAt stampedPaymentTransaction (created)AuditLog: invoice.paid
8

Audit Trail

Every mutation throughout the lifecycle writes an AuditLog entry with changeset (before/after), ipAddress, userAgent, severity, and sessionId. Reports show velocity, conversion, revenue trends using DealStageHistory.timeInPrevStage and Deal.closedAt.

AuditLog (every step)DealStageHistory (velocity)Reporting APIs

✅ Recommendations — All 10 Implemented

Every recommendation from the initial architecture review has been applied to the current Prisma schema.

✓ #1

Composite Indexes on tenantId + query fields

Added @@index([tenantId, status]), @@index([tenantId, createdAt]), @@index([tenantId, assignedUserId]) on Contact, Deal, Task, AuditLog, and all other high-traffic tables. Prevents full table scans on every tenant-scoped query.

✓ #2

UserRole Junction Table (replaces User.role String)

Added UserRole model linking User ↔ RoleDefinition many-to-many. User.role string kept as JWT compatibility fallback. Dynamic role creation by Client Admins now fully supported via POST /administration/roles.

✓ #3

Soft Delete (isArchived + deletedAt + deletedBy)

Contact, Deal, Organization all have isArchived: Boolean, archiveReason: String?, and deletedAt: DateTime?. Data is never hard-deleted — supports GDPR right-to-be-forgotten audit trail and data recovery.

✓ #4

ContactDeal Junction (replaces Deal.contactIds JSON array)

Added ContactDeal model with @@unique([contactId, dealId]), cascade deletes, and a role field (Primary Contact, Decision Maker, Technical Evaluator). Proper FK constraints — no more ghost IDs when a Contact is deleted.

✓ #5

Contact.ownerId and Deal.ownerId (separate from assignedUserId)

ownerId is set on creation and never updated. assignedUserId changes on reassignment. Enables accurate commission attribution and "who captured this lead" reporting without losing the original owner history.

✓ #6

Tenant.subscriptionStatus separate from Tenant.status

status = System Admin approval state (SANDBOX → ACTIVE → SUSPENDED). subscriptionStatus = PayMongo billing state (TRIAL → ACTIVE → PAST_DUE → CANCELLED). PayMongo webhooks update subscriptionStatus only — System Admin controls status independently.

✓ #7

AuditLog security fields (ipAddress, userAgent, sessionId, severity, changeset)

Every AuditLog entry now includes changeset: Json? (before/after object), ipAddress, userAgent, sessionId, and severity: INFO|WARNING|CRITICAL. Role changes and user deactivation log severity=WARNING. Supports security incident investigation and GDPR access logs.

✓ #8

Deal.closedAt timestamp

closedAt: DateTime? is stamped automatically in the workflow engine when stage.isWon || stage.isLost becomes true. The reporting API uses closedAt - createdAt for deal velocity calculations (average days to close).

✓ #9

Campaign.scheduledFor for future scheduling

Added scheduledFor: DateTime? to Campaign. Status can be SCHEDULED. The campaign send endpoint stamps sentAt on execution. Future: a cron job checks status=SCHEDULED AND scheduledFor <= now() to queue sends.

✓ #10

Stage.color (hex) for Kanban UI customization

Added color: String? (hex, e.g. #3fb950) to Stage. Seeded with default colors per stage (Discovery=indigo, Won=green, Lost=red). Client Admins can customize stage colors via PUT /crm/stages/:id without a code deployment.
